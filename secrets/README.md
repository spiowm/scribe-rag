# Секрети для контейнерів

Тека монтується в бекенд як `/run/secrets` (лише читання) і в нормальному
сценарії лишається **порожньою**.

## Як авторизувати agy — основний спосіб

Залогінитись усередині контейнера один раз. Токен одразу лягає в кіраїнг тому
`agy_home` і на диск проєкту не потрапляє взагалі.

```sh
docker-compose run --rm --no-deps backend agy
```

agy надрукує посилання й чекатиме код:

```
Authentication required. Please visit the URL to log in:
  https://accounts.google.com/o/oauth2/auth?...
Waiting for authentication (timeout 60s)...
Or, paste the authorization code here and press Enter:
```

Відкриваєш посилання у своєму браузері, копіюєш код, вставляєш у термінал.
**Вікно 60 секунд** — не встиг, просто запусти команду ще раз.

Браузер на сервері не потрібен: це той самий потік, що agy дає по ssh.

Далі `docker-compose up -d`. Токен живе в томі, agy сам освіжає його через
`refresh_token`, тож повторний логін потрібен лише якщо том знищено.

## Пересадка токена файлом — запасний спосіб

Лише для випадків, коли інтерактивний крок неможливий (автоматичне розгортання
на новий сервер). Секрет опиняється у файлі, тому після використання його треба
знищити.

```sh
secret-tool search service gemini \
  | grep '^secret = ' | sed 's/^secret = //' | tr -d '\n' > secrets/agy-token
chmod 600 secrets/agy-token
docker-compose up -d          # ентрипойнт перекладе токен у кіраїнг
shred -u secrets/agy-token    # одразу після успішного старту
```

`secrets/*` у `.gitignore`, але майте на увазі: `rsync`, `scp` чи архів теки
проєкту заберуть цей файл із собою — гіт від цього не захищає.
